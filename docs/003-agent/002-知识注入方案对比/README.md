# 019 · 参考：Agent 知识注入方案全景对比

> 🎯 目的：梳理当前 AI Agent 领域让 LLM「获取外部知识」的主流方案，理解它们的定位、差异和适用场景。
>
> 📅 编写时间：2026-07-06

---

## 这篇文章在回答什么问题？

最近有个热门讨论：**RAG、LLM Wiki、Skills、CLAUDE.md、Fine-tuning——这些到底有什么区别？什么时候该用哪个？**

简单说，它们都在解决同一个问题：**LLM 训练数据里没有你的项目知识，你怎么让它知道？**

但它们的解决思路完全不同，有的是「现查现用」，有的是「提前记住」，有的是「需要时再学」。这篇文章把这些概念串起来，结合我们课程里已经学过的内容，做一个全景对比。

---

## 一、一句话定义每个方案

| 方案 | 一句话 | 类比 |
|------|--------|------|
| **Fine-tuning（微调）** | 把知识「写入模型参数」，永久改变模型行为 | 让员工去读个学位——知识内化但成本高 |
| **RAG（检索增强生成）** | 先搜索知识库找到相关内容，注入 Prompt 再回答 | 员工遇到问题先查公司 Wiki |
| **LLM Wiki（上下文文档）** | 把结构化文档直接加载到上下文窗口 | 把手册摊在桌上随时翻 |
| **CLAUDE.md / AGENTS.md** | 每次对话自动加载的「项目入职手册」 | 新员工第一天发的 Welcome Kit |
| **Skills（渐进式披露）** | 按需加载的能力包——description 常驻，正文触发时才加载 | SOP 手册——目录在你桌上，具体章节用时再翻 |
| **Memory（Auto Memory）** | 模型在实践中自动沉淀的经验笔记 | 老员工的笔记本——踩过的坑记下来 |
| **MCP（Model Context Protocol）** | 实时连接外部工具和数据源 | 给员工配了内网系统的 API 权限 |

---

## 二、按「加载时机」分三类

```
事前加载（一直带着）     Fine-tuning → 内化到模型参数
                         CLAUDE.md → 每次对话自动读取

事中加载（用时再查）     RAG → 向量搜索 + 注入 Prompt
                         MCP → 实时调用外部服务

按需加载（触发了才加载）  Skills → 语义匹配 description → 加载正文
                         Memory → 对话中自动记录关键经验
```

---

## 三、详细对比

### 3.1 RAG vs Skills：两种「按需加载」的本质区别

这是最近讨论最多的对比。

| 维度 | RAG | Skills |
|------|-----|--------|
| **触发方式** | 向量相似度搜索（数学） | 语义匹配 description（LLM 理解） |
| **检索粒度** | 文档 Chunk（按相似度排序） | 能力包（按 Skill 描述匹配） |
| **加载内容** | 搜索结果片段（可能不完整） | 完整 SKILL.md + 引用文件 |
| **上下文利用** | 注入 Top-K 片段（可能丢失整体结构） | 渐进式披露（路由器→正文→附录） |
| **适用场景** | 海量非结构化文档（客服知识库） | 结构化操作流程（SOP、规范、模板） |

**核心区别**：RAG 解决「这里有相关段落，你看看有没有用」——适合知识碎片化的场景。Skills 解决「这个任务的标准做法是 XXX」——适合流程和规范固定的场景。

> 💡 我们在课程里学到的 Skills，本质上是一种**结构化的 RAG**——不是按文档块检索，而是按能力包加载。Skills 的 description 就是「能力检索的索引」，SKILL.md 就是「该能力的完整知识」。

---

### 3.2 CLAUDE.md vs LLM Wiki vs Skills

这三个是最容易混淆的——它们都是 Markdown 文件，都被 Agent 读取。

| | CLAUDE.md | LLM Wiki | Skills |
|------|----------|---------|--------|
| **加载时机** | 每次对话自动 | 需要时手动引用 | description 常驻，正文按需 |
| **内容量** | < 100 行（精简原则） | 可很大（几百 KB） | < 500 行/文件 + 引用 |
| **触发** | 自动（Push） | 手动引用或/自动读取 | 语义触发（Pull） |
| **定位** | 项目规则（每次都该知道） | 参考资料（偶尔查阅） | 操作流程（特定场景需要） |

**什么时候用什么**：

```
每次对话都需要的规则 → CLAUDE.md（Push）
偶尔参考的大型文档 → LLM Wiki（存储 + 引用）
特定场景下的专业流程 → Skills（语义触发）
```

> 💡 我们课程第 11 讲学的「渐进式披露」和第 16 讲学的「Push vs Pull」就是这套决策框架的基础。

---

### 3.3 Fine-tuning vs RAG/Skills

| | Fine-tuning | RAG / Skills |
|------|-----------|------------|
| **知识更新** | 重新训练（慢） | 改文件即可（快） |
| **成本** | GPU 训练（高） | 文件存储（低） |
| **知识范围** | 泛化到模型内部 | 精确到具体文档 |
| **幻觉控制** | 无法保证引用来源 | 可追溯到源文件 |

> 💡 2026 年的主流实践：**Fine-tuning 用于调整模型行为风格，RAG/Skills 用于注入具体知识**。两者互补，不是替代。

---

### 3.4 Memory（Auto Memory）vs CLAUDE.md

这是我们课程第 3 讲的内容——CLAUDE.md 是「你告诉 AI 的事」，Memory 是「AI 自己学到的事」。

```
CLAUDE.md  = 手动编写的长期规则 → 决定"系统被告知什么"
Auto Memory = 自动沉淀的实践经验 → 决定"系统在实践中学到了什么"
```

## 四、课程所学方案的定位图

把我们学的六个模块放在知识注入谱系里：

```
              知识的稳定性（越往右越固化）
   临时注入 ←──────────────────────────→ 持久记忆

   MCP           RAG        Skills      Memory      CLAUDE.md    Fine-tuning
   实时调用     向量搜索    语义按需    自动沉淀     每次加载     模型内化
   外部服务     文档片段    能力包      经验笔记     项目规则     参数更新
```

## 五、实战选型决策树

```
我要让 AI 知道什么？

├── 外部系统的实时数据（数据库、API）？→ MCP
├── 海量非结构化文档中的零散知识？→ RAG
├── 特定场景下的标准操作流程？→ Skills
├── 每次对话都需要知道的规则？→ CLAUDE.md
├── 偶尔参考的详细文档？→ LLM Wiki（引用）
├── 踩过的坑、学到的经验？→ Memory（自动沉淀）
└── 改变 AI 的回答风格和行为？→ Fine-tuning
```

---

## 六、总结

这些方案不是竞争关系——**一个成熟的 AI Agent 系统通常同时使用其中 3-5 种**。

举个例子，你已经在用的 Claude Code 就同时用了：
- **CLAUDE.md** → 每次对话知道项目基础规则
- **Skills** → 特定场景按需加载专业知识
- **Memory** → 自动记录项目经验
- **MCP** → 连接外部工具

RAG 在这个体系里对应的是「大量非结构化文档的检索」，Skills 对应的则是「结构化能力包的加载」。最近被比较，是因为它们都解决「让 AI 拥有外部知识」这个问题，但思路和适用场景不同。
